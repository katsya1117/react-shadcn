# Box UI Elements 23.0.0 → 26.0.0 更新の検証報告

| 項目 | 内容 |
| --- | --- |
| 目的 | SS 画面の Box Content Explorer（CDN の `elements/23.0.0`）を、`26.0.0` に上げても、このアプリが依存している動きが変わらないかを確かめる |
| 実施日 | 2026-11-25 |
| 結論 | **このアプリが依存している動きは、23.0.0 と 26.0.0 で、同じだった。** バージョンの数字を上げることに、技術的な障害は見つからなかった。ただし、**画面の見た目と、本物の Box での通信は、未確認**（第 5 章） |
| 読み込み方 | **CDN のまま**（方針: 維持）。変更する場所は、`index.html` の 2 行（`explorer.css`、`explorer.js` のバージョン）のみ |
| 関連資料 | [Box トークンのダウンスコープ設計書](./spec-box-token-downscope.md) / [SS 画面 技術仕様書](./spec-ss-screen.md) |

## 1. 前提の整理: React 19 は、関係しない

「React 19 なので、26 まで上げられるのでは」という前提について。**React のバージョンは、この更新の可否に関係しない。**

- 本アプリは、Box の部品を、**npm のパッケージではなく、CDN の完成品のバンドル**（`explorer.js`）で読み込んでいる（`node_modules` に `box-ui-elements` はない）。
- バンドルの中に、**React 18.3.1 が内蔵されている**（23.0.0 も 26.0.0 も同じ。バンドル内に `version:"18.3.1"` と `createRoot` がある）。Box の部品は、`window.Box.ContentExplorer` として、**自分の React で、`.box-container` に描画**する。
- そのため、アプリ本体の React（19）と、Box の部品の React（18.3.1）は、別々に動く。23.0.0 でも、26.0.0 でも、同じ。**React 19 だから上げられる、のではなく、もともと関係がない。**
- 上げられるかどうかは、「Box の部品の、このアプリが依存している動きが、変わらないか」で決まる。それを、以下で確かめた。

## 2. 検証の方法

2 つのバンドル（23.0.0、26.0.0）を、CDN から取得し、次の 2 つの方法で比べた。

| 方法 | 内容 |
| --- | --- |
| 静的な比較 | バンドルのソース（難読化済み）から、ラッパー（`window.Box.ContentExplorer`）の公開 API、`currentFolderId` の扱い、フォルダ取得の仕組みなどを、23 と 26 で比べた |
| 動作の比較（jsdom） | Node.js の jsdom 上で、各バンドルを読み込み、`new Box.ContentExplorer()` → `show()` を実行した。Box の API は、`requestInterceptor`（このアプリの試作のキャッシュと同じ方法）で、偽の応答に差し替えた。フォルダのクリック、パンくず、`navigateTo`、`hide()` などの操作を、**同じ手順で 23 と 26 に行い、結果を比べた** |

偽の Box は、`R` の下に `FolderA`（その下に `FolderA1`）、`FolderB`（ファイル 1 件）を持つ木。

## 3. 結果: このアプリが依存している動き

| # | 確認した動き | 23.0.0 | 26.0.0 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 公開 API（`show`、`hide`、`navigateTo`、`addListener`、`removeAllListeners`、`clearCache`） | あり | あり | 同じ |
| 2 | `show()` の後に、`navigate` イベントが届く。中身（`id`、`type`、`name`、`path_collection`）。**`useBoxExplorer` が依存している形** | 同じ（13 項目） | 同じ（13 項目） | 同じ |
| 3 | フォルダ行のクリック → `navigate`（行き先のフォルダ）と、`GET /folders/{id}` の 1 回 | 1 回 | 1 回 | 同じ |
| 4 | パンくずのクリック → `navigate`（そのフォルダ）。**履歴の規則が依存している動き** | 届く | 届く | 同じ |
| 5 | `navigateTo(id)` → `navigate` が届き、`GET /folders/{id}` の 1 回 | 届く | 届く | 同じ |
| 6 | **表示中のフォルダと同じ ID** へ `navigateTo` → `navigate` が届く（「戻る」の判定が依存） | 届く | 届く | 同じ |
| 7 | `currentFolderId` を渡す（復元）。ルートを経由せず、最初から復元先を取得する | `GET /folders/A1` のみ | `GET /folders/A1` のみ | 同じ |
| 8 | `show()` を、`hide()` せずに、もう一度呼ぶ | 再描画（イベントは増えない） | 同じ | 同じ |
| 9 | `hide()` の後に、同じインスタンスで、`show()` し直す | 動く | 動く | 同じ |
| 10 | `hide()` で、リスナーが外れ、コンテナが空になる | そうなる | そうなる | 同じ |
| 11 | `requestInterceptor` / `responseInterceptor` が、通信のたびに呼ばれる（試作のキャッシュが依存） | 呼ばれる | 呼ばれる | 同じ |
| 12 | フォルダ取得の `fields`（20 項目）、`sort`、`direction`、`limit`、`offset` | 同じ | 同じ | 同じ |
| 13 | フォルダ取得は、`forceFetch: true` 固定（試作のキャッシュの前提） | 固定 | 固定 | 同じ |
| 14 | `canDownload: false` などで、ダウンロードの項目が出ない | 出ない | 出ない | 同じ |
| 15 | `itemActions`（行の「…」メニューへの独自項目）が動く。`type` で、ファイルの行だけに出し分けられる。`onAction` に、アイテムが渡る | 動く | 動く | 同じ |
| 16 | ファイル名のクリックで、`select` イベントが**届かない**（`canPreview: false`） | 届かない | 届かない | 同じ |
| 17 | アプリが CSS で頼っている Box のクラス名（[SS.tsx](../src/pages/SS.tsx) の `.box-container` の `[&_.be-logo]:hidden`、`[&_.be-header]:pl-3`）が、DOM にある | `.be-logo` 1、`.be-header` 1 | `.be-logo` 1、`.be-header` 1 | 同じ（`.be-logo-container` は、どちらにもない。もともと効いていない指定） |

## 4. 違いがあった点

| # | 違い | このアプリへの影響 |
| --- | --- | --- |
| 1 | **描画の仕組み**: 23 は旧式の `ReactDOM.render`、26 は `createRoot` | 画面を離れるときの `hide()` の内部の実装が違う。動作の結果は同じ（上の 9、10） |
| 2 | **`show()` の前に `hide()` を呼ぶ**: 23 は例外（React error #40）、26 は例外なし | SS.tsx は、`show()` 済みのときだけ `hide()` を呼ぶ（`hasShownRef`）ため、影響なし。26 のほうが安全 |
| 3 | **通信の HTTP ヘッダー**: 26 は、`X-Box-Client-Version` を、新しく送る（23 は `X-Box-Client-Name` まで） | カスタムヘッダーのため、ブラウザは、事前確認（CORS preflight）を行う。Box の API は、Box 自身の部品が送るヘッダーを許可するはずだが、**社内のプロキシや、Box の CORS 設定の影響を、本物の環境で確認する必要がある**（第 5 章） |
| 4 | **CSS の大きさ**: 498 KB → 888 KB。`:root` のカスタムプロパティ 752 個 → 1,813 個（`--bp-*` が約 1,000 個増える。Box の新しいデザインの部品用） | アプリの `index.css`（100 個）と、**名前の重なりは、0 件**。全体に効く素のセレクタ（`html`、`body`、`*` など）は、23 も 26 も、ほぼ同じで、`:root` のみ。**見た目への影響は、目で見ないと分からない** |
| 5 | **ファイルの大きさ**: `explorer.js` 3.7 MB → 4.3 MB | 初回の読み込みが、約 0.6 MB 増える |

## 5. 未確認のこと（本物の環境で確認が必要）

| 項目 | 理由 |
| --- | --- |
| **画面の見た目** | jsdom には、レイアウトも描画もない。CSS が約 1.8 倍になり、新しいデザインの部品が入っているため、表の列、行の高さ、ボタンの形が、変わっている可能性がある。アプリが Box のクラス名に頼って隠している部分（`.be-logo`、`.be-header`）は、26 にも同じ名前であることを、DOM で確認した（第 3 章 17）。ただし、**実際に隠れて、余白が崩れないか**は、目で確認する |
| **本物の Box との通信** | 通信は、偽の応答に差し替えた。実際の API で、`X-Box-Client-Version` ヘッダーが、CORS の事前確認を通るか（第 4 章 3） |
| 表示サイズ（`size: "large"`）、日本語の表示 | 描画を見ていない |
| 実際の操作感（クリック、スクロール、フォルダが多いとき） | jsdom では、仮想リストの描画が限定される |

## 6. 副次的に分かったこと

| # | 内容 | 影響 |
| --- | --- | --- |
| 1 | **`itemActions` は、23.0.0 にも、すでにある**（26 の新機能ではない） | ファイルのコラボレーション対象を選ぶ機能（`[FILE-COLLAB]`）は、バージョンを上げなくても、使える |
| 2 | **ファイル名のクリックは、`select` イベントを発火しない**（`canPreview: false` のとき。23・26 とも） | 行のクリックで、ファイルを選ぶ案が成立しない根拠が増えた。`itemActions` を採用した判断が、裏づけられた |
| 3 | **ファイルの「…」メニューに、「Share」（共有リンク）が、既定で出る**（23・26 とも）。`canShare: false` と `canSetShareAccess: false` を渡すと、消える | **現在の本番にも、すでに出ている可能性がある**（メニューのボタン自体が、「Share」のためにある）。共有リンクの作成を、許可しない運用なら、`show()` のオプションに、`canShare: false` を足す必要がある。**別件として、判断が要る** |

## 7. 上げるときの手順と、確認項目

### 7.1 変更（実施済み: 2026-11-25）

1. `index.html` の 2 行（`explorer.css`、`explorer.js`）の `23.0.0` を、`26.0.0` にした。**CDN のまま**。
2. 設計書の、現在のバージョンを述べる箇所（`spec-ss-screen.md`、`spec-box-token-downscope.md`）を、`26.0.0` に直した。`23.0.0` のソースを確認した結果として書かれている箇所（`spec-box-folder-cache.md`、`report-box-api-call-reduction.md`、`spec-use-folder-navigation.md`、`useBoxExplorer.md`）は、「26.0.0 でも同じ」と、注記した。
3. 「Share」（共有リンク）の項目を、`canShare: false`、`canSetShareAccess: false` で、出さないようにした（第 6 章 3。[SS.tsx](../src/pages/SS.tsx)）。

### 7.2 上げたあとの確認（本物の環境）

1. 領域を開いて、Explorer が表示される（ロゴとヘッダーが隠れている）。
2. 見た目が、許容できる（列、行、ボタン）。
3. フォルダを開く、パンくずを押す、「戻る / 進む」を押す。履歴が、正しく動く。
4. 他の画面から戻って、前回のフォルダが復元される。
5. 開発者ツールのネットワークで、Box の API への通信が、成功している（CORS のエラーがない。事前確認が通っている）。
6. ダウンロードの項目が、出ない。

### 7.3 戻し方

`index.html` の 2 行を、`23.0.0` に戻すだけ。

## 8. 検証の再現

検証に使ったスクリプトは、作業用の場所（リポジトリの外）に置いたもので、リポジトリには入れていない。次回の更新時に、同じ確認を行うなら、第 2 章の方法（jsdom で、バンドルを読み込み、偽の API で、`show()` から `navigate`、パンくず、`navigateTo`、`hide()` までを比べる）で、再作成できる。必要なら、リポジトリに、検証用のスクリプトとして、追加できる。
