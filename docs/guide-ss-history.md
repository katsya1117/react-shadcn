# SS 画面の「履歴」の作られ方（完全解説）

| 項目 | 内容 |
| --- | --- |
| 対象 | SS 画面（コラボレーション設定）の、「戻る / 進む」ボタンと、他の画面から戻ったときの「前回のフォルダの復元」を支える、フォルダの履歴 |
| 想定する読者 | このコードを初めて読む人。React や Redux の詳しい知識は、前提にしない |
| 実装 | [src/hooks/useFolderNavigation.ts](../src/hooks/useFolderNavigation.ts)（本体）、[src/pages/SS.tsx](../src/pages/SS.tsx)（初期値の用意）、[src/redux/slices/ssSlice.ts](../src/redux/slices/ssSlice.ts)（保存） |
| 詳細な仕様 | [useFolderNavigation 仕様書](./spec-use-folder-navigation.md)（判定の表・不具合の経緯）。本書は、それを、図と例で説明し直したもの |
| 確認の方法 | 本書の例は、すべて、実際にフックを動かして確かめた（2026-11-25）。ただし、本物の Box の Explorer での確認は、未実施 |

## 0. 先に結論

1. 履歴は、**「訪れたフォルダの並び」と、「いま、その並びのどこにいるか（位置）」の 2 つ**でできている。
2. **フォルダを開くたびに、並びの末尾に足す。** フォルダのクリックでも、パンくずのクリックでも同じ。
3. **「戻る」「進む」は、並びを変えず、位置だけを動かす。**
4. **戻ったあとに、新しいフォルダを開くと、位置より先の並びは捨てられる。**
5. この動きは、**ブラウザの「戻る / 進む」と同じ**。

## 1. 用語

| 用語 | 意味 |
| --- | --- |
| ルート | この画面で最初に開く、領域の一番上のフォルダ。以下の例では `R` と書く |
| 現在のフォルダ | いま、画面に表示しているフォルダ |
| 履歴 | 訪れたフォルダの、**フォルダ ID の並び**。例: `[R, A, B]` |
| 位置 | 履歴の中で、いま、どこにいるかを示す**番号**（先頭が 0）。例: 履歴 `[R, A, B]`、位置 2 なら、いま B にいる |
| Explorer | 画面の左に出ている、Box のファイル一覧の部品。フォルダの表示は、Explorer が行う |
| 知らせ（navigate イベント） | Explorer が、「このフォルダを表示した」と、こちらに教えてくる合図。**履歴は、この知らせを受けて更新する** |

履歴のイメージ（`^` が位置）:

```
履歴 : [ R , A , B , C ]
位置 :               ^        ← 位置 3（いま C にいる）
```

## 2. 履歴は何のためにあるか

| 用途 | 内容 |
| --- | --- |
| 「戻る / 進む」ボタン | 画面上部のパスバーのボタン。履歴を使って、前後のフォルダへ移る。履歴の先頭にいれば「戻る」は押せず、末尾にいれば「進む」は押せない |
| 前回のフォルダの復元 | 他の画面へ移ってから戻ったときに、前回見ていたフォルダを開き直す（第 6 章）。履歴も、前回の続きから使う |

## 3. 基本ルール: フォルダを開くと、末尾に足す

利用者が、**Explorer でフォルダをクリックして開く**と、Explorer から「知らせ」が届く。履歴は、次のとおりに更新される。

1. 位置より**先**にある履歴を、捨てる（先がなければ、何もしない）。
2. 開いたフォルダを、末尾に足す。
3. 位置を、足した末尾に動かす。

### 例: A、B、C と順に開く

```
開始     : 履歴 [R]           位置 0   画面 R
A を開く : 履歴 [R, A]        位置 1   画面 A
B を開く : 履歴 [R, A, B]     位置 2   画面 B
C を開く : 履歴 [R, A, B, C]  位置 3   画面 C
```

## 4. 「戻る」「進む」: 位置だけを動かす

| ボタン | 動作 |
| --- | --- |
| 戻る | 位置を 1 つ**前**へ動かし、その位置のフォルダへ移るよう、Explorer に指示する |
| 進む | 位置を 1 つ**後**ろへ動かし、その位置のフォルダへ移るよう、Explorer に指示する |

- **履歴の並びは、変わらない。**（位置だけが変わる）
- 先頭にいるときの「戻る」、末尾にいるときの「進む」は、何も起きない。
- 指示を受けた Explorer は、そのフォルダを表示し、「知らせ」を返してくる。この知らせは、**「戻る / 進む」の結果**として扱い、履歴は触らず、現在のフォルダの表示だけを更新する（第 8 章）。

### 例: 続き（C にいる状態から）

```
戻る → 位置 2   履歴 [R, A, B, C]  画面 B   （並びは変わらない）
戻る → 位置 1   履歴 [R, A, B, C]  画面 A
進む → 位置 2   履歴 [R, A, B, C]  画面 B
```

```
履歴 : [ R , A , B , C ]
位置 :           ^        ← 位置 2 (B)。右にまだ C が残っているので「進む」が押せる
```

## 5. 戻ったあとに、新しく開くと、先の履歴は捨てられる

位置が、末尾ではなく途中にあるときに、フォルダを開くと、**位置より先の履歴は捨てられて**、新しく開いたフォルダが、その後ろにつく。ブラウザで、戻ってから別のページを開くと、「進む」が使えなくなるのと同じ。

### 例: 続き（B にいて、先に C が残っている状態から）

```
D を開く → 履歴 [R, A, B, D]  位置 3  画面 D   （C が捨てられた。「進む」は押せない）
```

```
開く前 : [ R , A , B , C ]      位置 2 (B)
                      ↑ 位置より先（C）は、捨てられる
開いた後: [ R , A , B , D ]      位置 3 (D)
```

## 6. パンくず: フォルダのクリックと同じ

Explorer の上にある、パンくず（`All Files > センター > フォルダ …` の部分）を押して、上の階層へ移ったときも、Explorer から「知らせ」が届く。**フォルダをクリックしたときと、まったく同じ規則**で、履歴の**末尾に足す**。

- すでに履歴にあるフォルダ（ルートなど）へ戻る場合でも、**足す**。履歴に、同じフォルダが、重複して入ることがある（ブラウザと同じ）。
- そのおかげで、パンくずで上の階層へ移ったあとに「戻る」を押すと、**押す前にいたフォルダへ戻れる**。

### 例: 続き（D にいる状態から、パンくずで A へ）

```
パンくずで A → 履歴 [R, A, B, D, A]  位置 4  画面 A   （A が末尾に足された）
戻る         → 履歴 [R, A, B, D, A]  位置 3  画面 D   （押す前にいた D に戻れる）
```

> 以前は、すでに履歴にあるフォルダなら、足さずに、位置だけを動かしていた。その場合、上の例で「戻る」を押すと、D ではなく R へ行き、押す前のフォルダに戻れなかった。結果が、フォルダによって「足される / 足されない」で変わり、分かりにくかったため、2026-11 に、いまの規則へ変更した。

### 全体の流れ（ここまでの例を通して）

| 操作 | 履歴 | 位置 | 画面 | 戻る | 進む |
| --- | --- | --- | --- | --- | --- |
| 開始 | `[R]` | 0 | R | × | × |
| A を開く | `[R, A]` | 1 | A | ○ | × |
| B を開く | `[R, A, B]` | 2 | B | ○ | × |
| C を開く | `[R, A, B, C]` | 3 | C | ○ | × |
| 戻る | `[R, A, B, C]` | 2 | B | ○ | ○ |
| 戻る | `[R, A, B, C]` | 1 | A | ○ | ○ |
| 進む | `[R, A, B, C]` | 2 | B | ○ | ○ |
| D を開く | `[R, A, B, D]` | 3 | D | ○ | × |
| パンくずで A | `[R, A, B, D, A]` | 4 | A | ○ | × |
| 戻る | `[R, A, B, D, A]` | 3 | D | ○ | ○ |
| D の知らせが、もう一度届く | 変わらない | 3 | D | ○ | ○ |

（最後の行は、第 7 章）

## 7. 同じ知らせが、二重に届いたら、無視する

Explorer は、同じフォルダの「知らせ」を、続けて 2 回送ってくることがある（その保険）。**いまいるフォルダと同じ知らせは、何もしない。** 履歴にも、位置にも、画面にも、変化はない。

## 8. 知らせが来る理由は 5 つ: 上から順に判定する

「知らせ」を受けたとき、履歴をどう扱うかは、**なぜその知らせが来たか**で変わる。上から順に調べ、当てはまったところで終わる。

| 順 | 理由 | 履歴の扱い |
| --- | --- | --- |
| ① | 復元中（第 9 章） | 触らない |
| ② | 「戻る / 進む」で向かっていたフォルダの知らせ | 触らない（ボタンを押した時点で、位置は更新済み）。画面の表示だけ更新する |
| ③ | 初回表示: 初めて入った画面で、ルートの知らせが届いた（現在のフォルダは、名前のない仮の値） | 触らない。現在のフォルダを実データに差し替える |
| ④ | いまいるフォルダと同じ知らせ（二重の知らせ） | 何もしない |
| ⑤ | 上のどれでもない = 利用者の操作（フォルダのクリック、パンくず） | 第 3・5・6 章の規則で、足す |

### ②の補足: 「向かっているフォルダ」を覚える理由

「戻る」を押すと、履歴の位置は、その場で動く。同時に、Explorer へ「A へ移って」と指示し、**「いま向かっているのは A」と覚えておく**。届いた知らせが A なら、「戻るの結果」と判断する（②）。

覚える理由は、**「戻る」が失敗することがあるため**。たとえば、A の権限が外れた、A が削除された、通信が失敗した、といった場合、Explorer は A を表示できず、知らせも来ない。このとき、次のようになる。

| 場面 | 起きること |
| --- | --- |
| 「戻る」を押す（失敗。知らせは来ない） | 位置は A へ動くが、画面は B のまま |
| 利用者が、別のフォルダ X を開く | X の知らせが届く。**覚えていた「向かう先」（A）と違う**ので、「戻るの結果」ではなく、**利用者の操作**として扱う（④）。履歴は `[R, A, X]` になり、画面と履歴が、一致する |

> 以前は、「戻る」を押したあとの知らせを、**何であっても**、「戻るの結果」と見なしていた（true / false の旗で判定）。失敗すると、次の操作が取り違えられ、X が履歴に足されず、画面と履歴がずれていた。向かう先のフォルダ ID を覚える方式にして、解消した（詳細は [spec-use-folder-navigation.md](./spec-use-folder-navigation.md) の 8.6）。

## 9. 他の画面から戻ったときの「復元」

### 9.1 履歴の保存

履歴・位置・現在のフォルダは、**フォルダを移るたびに**、Redux（アプリ全体の記憶領域）の `ss` スライスに、**ルート（領域）ごとに**保存される（`setFolderHistory`、`setCurrentFolder`）。

| 保存するもの | 内容 |
| --- | --- |
| 履歴 | フォルダ ID の並び |
| 位置 | 履歴の中の番号 |
| 現在のフォルダ | ID・名前・パス |

### 9.2 復元の流れ

1. 他の画面（例: ユーザー管理）へ移る。SS 画面は、いったん消えるが、Redux の保存は残る。
2. 再び、SS 画面に入る。画面の作り直しで、保存してあった履歴・位置・現在のフォルダを読み出し、フックの**初期値**にする。
3. 保存してあった現在のフォルダが、ルートと違えば、「**復元先**」とする。Explorer は、復元先を、最初から表示する。
4. 復元先の「知らせ」が届いたら、**復元完了**。現在のフォルダを更新するが、**履歴は触らない**（保存してあったものが、そのまま使われる）。
5. 復元が終わるまで、画面はスケルトン（読み込み中の表示）になる。

→ 前回の続きから、「戻る / 進む」が使える。

### 9.3 復元の途中で届く知らせ

復元の途中は、上の①の扱い。ルートの知らせが届いたら、復元先へ移るよう Explorer に指示するだけで、履歴は触らない。

### 9.4 初期値の補正

画面の作成時に、保存してあった履歴が空、または、先頭がルートでない場合は、**先頭にルートを足す**（[SS.tsx](../src/pages/SS.tsx) の `initialHistory`）。初めて入るときは、履歴は `[R]`、位置は 0 から始まる。

## 10. 履歴が消える場面

| 場面 | 履歴 |
| --- | --- |
| 他の画面へ移る（サイドメニューなど） | **残る**（戻ると、復元される） |
| 「ShareArea に戻る」ボタン | **消える**（その領域の履歴・現在のフォルダを破棄する）。次に入ると、ルートから始まる |
| 管理者ではない、または管理者の確認に失敗して、SS 画面から弾かれた | **消える**（その領域の保存状態を破棄する。権限のない人の記録を残さないため） |
| ブラウザの再読み込み、タブを閉じる | **消える**（Redux は、メモリ上にあり、ブラウザへ保存していない） |
| 別の領域（別のルート）へ移る | その領域は、別の履歴（領域ごとに、別々に持つ） |

## 11. 画面の表示との関係

| 画面の部分 | 何を見ているか |
| --- | --- |
| 「戻る」「進む」ボタンの押せる / 押せない | 位置（先頭でなければ「戻る」、末尾でなければ「進む」が押せる） |
| パスバー（`\share\…` の表示）、右の、コラボレーション画面 | **現在のフォルダ**（履歴ではない） |
| Explorer 内のパンくず | Explorer 自身が作る。履歴とは別（押した結果が、履歴に足される） |

## 13. よくある疑問

**Q. パンくずで戻ったのに、履歴が増えるのはなぜ?**
A. ブラウザと同じ動きにしているため。ブラウザも、リンクで戻っても、履歴は積まれる。積むことで、「戻る」が、押す前のフォルダへ戻れる。

**Q. 同じフォルダが、履歴に何度も出てくる。バグでは?**
A. バグではない。「A → B → パンくずで A」とたどると、`[R, A, B, A]` になる。

**Q. 「進む」が押せなくなった。**
A. 戻ったあとに、新しいフォルダを開いたため（第 5 章）。位置より先の履歴は捨てられる。

**Q. 履歴は、どこまで増える?**
A. 上限はない。

**Q. 他の画面から戻ると、前回のフォルダが開くのはなぜ?**
A. 履歴と現在のフォルダが、Redux に保存されているため（第 9 章）。「ShareArea に戻る」ボタンで抜けると、保存は破棄される。

**Q. 履歴を、ブラウザの再読み込みの後も、残せる?**
A. 現状は、残らない。残すには、Redux の内容を、ブラウザへ保存する仕組み（localStorage など）が要る。

## 14. 注意点（未確認・既知の制約）

- **本物の Box の Explorer での確認は、未実施。** 本書は、Explorer の「知らせ」を、テストで模擬して確認した結果に基づく。
- 「戻る」に失敗したとき、位置は、向かった先に動いたままになる。次の操作で、その位置より先の履歴は捨てられる（第 8 章の例では、B が履歴から消える）。
- Explorer が、いまのフォルダを二重に知らせる場合に、「戻る」の結果より先に届くと、取り違える可能性がある（未確認）。
- 本番環境は、フォルダ取得のキャッシュ・更新ボタンの試作を追加する前の状態。履歴の規則は、そのフックにも、同じ修正が当たる（試作側のコピー `useBoxExplorerWithRefresh` にも、同じ修正を入れてある）。
