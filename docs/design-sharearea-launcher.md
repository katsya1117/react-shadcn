# 設計: 共有領域のランチャー（他センターから共有されたフォルダの表示）

状態: 検討中（方針は決定済み。実装前）

関連: [memo-sharearea-box-visibility.md](./memo-sharearea-box-visibility.md)（初期の検討の経緯。レポート方式に決まる前のもの）、[screen-spec-user-sharearea-ss.md](./screen-spec-user-sharearea-ss.md)（現在の画面仕様）

## 1. 目的と方針

### 1.1 課題
現在の ShareArea は、ユーザーが **所属（メンバー）またはゲストのセンター** だけをカードに出す。
他センターから、**センターの下層フォルダにだけ共有（コラボレート）された領域** は出ない。
ランチャー（目的の領域へ移動するための画面）の役割が満たされていない。

### 1.2 方針
1. 画面を 2 つに分ける（管理画面への切り出しは保留。2 章）。
   - **ランチャー**: 全員が使う。所属・ゲスト・共有を、種別が見分けられるように出す。
   - **管理画面**: 従来の ShareArea。コラボレーション設定とメンバー一覧を持つ。
2. 共有された領域は、**共有されたフォルダごとに 1 枚のカード** にする。カードから、その領域へ直接移動する（センターのトップから降りていかない）。
3. 共有の情報の**本元**は、**Box 管理コンソールの「コラボレーションレポート」（CSV）を、バッチで DB に取り込んだもの**（毎日、全行入れ替え）。
4. SS 画面でのコラボレーションの追加・変更・削除は、**上書きテーブル**に記録して、本元の上に重ねる。レポートが反映するまでの遅れ（最大 1 日）を埋めるためのもの。上書きの書き込みに失敗しても、1 日遅れに戻るだけで、操作自体は成功させる。
5. ランチャーの一覧表示と、Box Drive ボタンの押下では、**Box を呼ばない**。
6. 名前・経路の変更、Box で直接行った共有、グループのメンバーの出入りへの追従は、**レポートの取り込みのたび**に行う（最大 1 日遅れ）。この遅れは許容し、画面で案内する（8 章）。

### 1.3 採用しなかった案（概要）
| 案 | 内容 | 採用しない理由 |
|---|---|---|
| ユーザーごとの件数管理 | 利用者ごとに共有の件数を持つ | 管理が複雑 |
| ユーザーとして Box を探索 | `withUserSubject` で、センター配下をたどる | 一覧を開くたびに API を消費する。深いフォルダはたどる回数が増える |
| 表示のたびに名前を取得 | `folders/{id}` で最新の名前を取る | 名前の追従のためだけに API を消費するのは割に合わない |
| 夜間バッチで Box API を呼ぶ | 共有されたフォルダごとに `GET /folders/{id}` を呼ぶ | フォルダの数だけ API を消費し、呼び出し制限を圧迫する（バックエンド担当の指摘） |
| コラボレーション追加時に DB へ書く（これだけで完結させる） | SS 画面の操作で、DB に記録する | 既存の共有・アプリを通さない共有が入らない。→ 本元はレポートとし、SS の操作は「上書き」として重ねるだけにした |
| 押すたびに Box で最新のパスを取る | Box Drive ボタンで `GET /folders/{id}` | 押した回数だけ API を消費する。レポートの更新を待つ方針にした |
| Box の Webhook | 変更を通知で受ける | 受け口の用意・権限など、導入のハードルが高い |

## 2. 画面

### 2.1 ランチャー
区分けは 2 つ。それぞれを、角丸のグレーのブロック（背景より一段濃い slate）で囲む。見出しは「アイコン + 英字の小見出し + タイトル + 件数」で、色で分ける。どちらもカードで（平らな見た目。影や浮き上がりは付けない）、共有は 2 段組。

```
MY CENTER（primary）  所属センター [4]
  [センターA] [センターB] [センターC]            ← カード（3 列）

MY COLLABORATION（sky） 共有された領域 [9]   [🔍 絞り込み]

  🏢 第2ソフトウェア開発センター  JCLGD2SWDV  [5]      ← センターごとの小見出し
  ┌─────────────────────┐ ┌─────────────────────┐
  │ 📁 見積資料  共有 編集者  │ │ 📁 契約書  共有 ビューアー │
  │ JCLGD2SWDV › … › 見積資料 │ │ JCLGD2SWDV › … › 契約書  │
  │            [Box][Drive] │ │            [Box][Drive] │
  └─────────────────────┘ └─────────────────────┘
  [ 他 1 件を表示 ]

  🏢 第3ネットワークセンター  JCLGD3NW  [4]
  ┌─────────────────────┐ ┌─────────────────────┐
  │ …                    │ │ …                    │
```

- 共有は、**親のセンターごとにまとめる**。センターの区分けは、すべて出す。小見出しは、センターの表示名、英字のフォルダ名、件数の 1 行で、枠や罫線は付けず、余白でまとまりを作る。
- 縦に長くならないよう、センターごとに最初は 4 件のカードだけ出し、超える分は「他 N 件を表示」で広げる（センターごとに独立）。
- 共有が 5 件を超えるときだけ、絞り込み（センター名・フォルダ名・パス）の入力欄を出す。絞り込み中は、一致するカードをすべて出し、一致のないセンターは出さない。
- 所属・ゲストのカードと共有のカードは、同じ骨格（フォルダアイコン / フォルダ名とバッジ / 下段のボタン）にそろえる。違いは色味と、共有だけがフルパスの行を持つこと。
- 見た目は平ら（影や浮き上がり、グラデーションは付けない）。

### 2.2 共有のカード
| 位置 | 内容 | 元の項目 |
|---|---|---|
| 1 行目 | フォルダ名、「共有」とロールのバッジ（編集者 / ビューアー） | フォルダ名、権限 |
| 2 行目 | フルパス（`センター名 › 経路 › フォルダ名`）。2 行まで折り返す | レポートの Path |
| 下段 | Web Box / Box Drive のボタン | フォルダ ID、経路 |

- コラボレーション設定のボタンは出さない（管理画面の機能）。
- **フルパスは組み立てて出す**: `センター名（Path の 3 番目）+ 経路 + フォルダ名`。先頭は表示名ではなく、**Box 上のフォルダ名（英字）**。Box Drive のパスにそのまま使うため。
- 表示名（管理者が付ける呼び名）は設けない。フォルダ名は、レポートの取り込みで更新される Box 上の名前。
- **センター直下のとき**（経路が空）: フルパスはフォルダ名とセンターが分かる内容なので、フルパスの行を出さない。
- **省略**: 長いときは、先頭の 1 つ（センター名）と末尾の 2 つを残して、間を `…` にする。全文は、マウスを載せたときに出す（`title`）。
- センターの表示名（「〇〇センター」）は、カードではなく、センターごとの小見出しに出す（センターのマスタの `center_name`）。
- 並び順: センター名、次にフォルダ名。
- 「見つからない」の状態は持たない。削除されたり、共有が外れたりしたものは、次の取り込みで行ごと消える。

### 2.3 ボタンの動き
| ボタン | 動き | Box への問い合わせ |
|---|---|---|
| Web Box | `https://app.box.com/folder/{フォルダ ID}` を開く | なし（ID なので、改名の影響を受けない） |
| Box Drive | DB の経路から、ローカルパスを組み立てて開く | なし |
| 起動 | センター単位の現状の挙動 | 要確認（共有されたフォルダでの扱いは未決） |

## 3. DB の構成

### 3.1 コラボレーションレポートの取り込み先（`collaboration_report`）
レポートの 1 行（**コラボレーション × メンバー 1 人**）が、テーブルの 1 行。グループ宛てのコラボレーションは、レポートの側で、メンバーごとの行に展開されて出る（メンバーの個人名とメールアドレスが入る）。取り込みのたびに、**全行を入れ替える**。

| 列 | 内容 | 元 |
|---|---|---|
| `collaboration_id` | コラボレーション ID。グループ宛ては、メンバーの行すべてで同じ値の想定（要確認） | レポートの Collaboration ID（出力は既定でオフ。オンにする） |
| `collaborator_login` | メンバーのメールアドレス。ユーザーとの突き合わせに使う | Collaborator Login |
| `item_id` | 共有されたフォルダの ID | Item ID |
| `item_name` | フォルダ名 | Item Name |
| `permission` | `editor` / `viewer`（取り込み時に、「編集者」「ビューアー」から変換） | Collaborator Permission |
| `center_folder_id` | センターのフォルダの Box ID | Path ID の 3 番目（4.3） |
| `center_name` | センターのフォルダ名（英字） | Path の 3 番目 |
| `path_names` | センターより下の名前の並び（共有されたフォルダ自身を除く） | Path の 4 番目以降（末尾を除く） |
| `imported_at` | 取り込んだ時刻 | 取り込み処理 |

- 主キー: （`collaboration_id`, `collaborator_login`）。索引: `collaborator_login`。
- 個人情報を減らすため、メンバーの名前、所有者、招待者などの列は、取り込まない。
- 取り込む行は、Item Type が Folder で、Path が 4 要素以上のものだけ（4.3）。

### 3.2 センターのマスタ（既存）
`center_cd` / `center_name` / `folder_name` に加えて、**センターの Box フォルダ ID の列がある**（確認済み）。

| 応答の項目 | 元 | 例 |
|---|---|---|
| `centerName`（Box 上のフォルダ名。英字。フルパス・Box Drive のパス用） | `collaboration_report.center_name`（Path の 3 番目） | `JCLGD2SWDV` |
| `centerLabel`（表示名。カードに出す） | マスタの `center_name`（`center_folder_id` で引く） | 第2ソフトウェア開発センター |

`centerName` は、マスタの `folder_name` ではなく、Path の値をそのまま使う。マスタが古くても、Box 上の実際の名前で Box Drive のパスを作れる。

### 3.3 ユーザーとグループ
ログインユーザーのメールアドレスが、`collaborator_login` と一致する。突き合わせは、大文字小文字を区別しない（要確認: アプリのユーザー情報のメールアドレスと、Box のログインが同じ値か）。

本元（レポート）は、グループ宛てがメンバーごとに展開済みなので、グループの所属は要らない。**上書きテーブルの `group` 宛ては展開されていない**ため、ユーザーが属するグループを、**アプリの既存のグループの所属テーブル**で引く。SS 画面で相手として選ぶグループと、同じ識別子（ID か名前）で結べることが前提（9 章）。

### 3.4 SS の操作の上書き（`collaboration_overlay`）
SS 画面でのコラボレーションの追加・変更・削除のうち、**まだレポートに反映されていないもの**だけを持つ小さなテーブル。本元の上に重ねて、一覧を作る。

| 列 | 内容 |
|---|---|
| `collaboration_id`（主キー） | Box が返すコラボレーション ID |
| `op` | `add`（追加）/ `update`（権限の変更だけ）/ `delete`（削除） |
| `principal_type` / `principal_key` | `user`（メールアドレス）または `group`（グループの識別子）。`add` のとき |
| `permission` | `editor` / `viewer`。`add` と `update` のとき |
| `item_id` / `item_name` / `center_folder_id` / `center_name` / `path_names` | SS 画面の現在地（`currentFolder`）の値。`add` のとき |
| `created_at` | 操作した時刻 |

- `update` は、本元の行（レポート由来）の権限を置き換えるために使う。`add` の行に対する権限変更は、その行の `permission` を更新する。
- `delete` は、本元の行を隠すために使う。**削除を入れる理由**: 入れないと、外した共有が、レポートに反映されるまで一覧に残る（開こうとすると Box に拒否される）。

## 4. レポートの設定と取り込み

### 4.1 Box 管理コンソールのレポート設定
| 項目 | 設定 |
|---|---|
| 種類 | コラボレーションレポート |
| 列 | Collaboration ID をオンにする（既定はオフ）。Item ID / Item Name / Item Type / Path / Path ID / Collaborator Login / Collaborator Type / Collaborator Permission はオンのまま |
| フォルダ | `share` フォルダを指定する（その下の階層を含む。継承されたコラボレーションは含まれない） |
| 相手の種類 | 管理対象のユーザーまたはグループ（外部ユーザーは除く） |
| 招待日 | **すべての期間**（期間で絞らない。全件の出力にして、削除を検知できるようにするため） |
| 繰り返し | 週 1 回の設定を、月〜金で 5 本作る（毎日更新になる） |

### 4.2 取り込みの手順（バッチ）
1. レポートの出力（実行ごとのフォルダにある、`Page_#` に分かれた CSV）を、すべて取得する。
2. 行を変換する（4.3）。対象外の行は捨てる。
3. 作業用のテーブルに入れ、正常に読めたことを確認してから、`collaboration_report` と入れ替える（途中で失敗しても、前回の内容が残る）。
4. 取り込みに失敗したとき、または行数が極端に少ないときは、入れ替えずに前回の内容を残し、通知する。
5. 入れ替えに成功したら、**レポートの実行時刻**（出力のフォルダ・ファイル名の `collaborations_run_on_YYYY-MM-DD-HH-MM-SS`）を記録し、上書きテーブルの後始末を行う（4.4）。

### 4.3 行の変換の規則
Path と Path ID は、要素の数が同じで、位置が 1 対 1 に対応する。先頭は `0` / 「すべてのファイル」。末尾はフォルダ自身。**センターのフォルダは、常に 3 番目の要素。**

```
Path    : すべてのファイル / share / JCLGD2SWDV   / 2024年度 / 営業部 / 見積資料
Path ID : 0              / 111   / 370700000001 / 222      / 333    / 370710000001
位置    :       1           2          3            4          5        6
```

| 取り出すもの | 規則 |
|---|---|
| `center_folder_id` / `center_name` | Path ID / Path の 3 番目 |
| `path_names` | Path の 4 番目から、末尾の 1 つ手前まで（上の例では `2024年度`, `営業部`） |
| `item_name` | Path の末尾（Item Name と同じ） |
| 対象外 | Item Type が Folder でない行、Path が 3 要素以下の行（センターそのものへの共有。所属・ゲストのカードで出る） |

### 4.4 上書きテーブルの運用

**書き込み（SS 画面の操作。Box の操作が成功したあと）**

| 操作 | 上書きテーブル |
|---|---|
| 追加 | `add` の行を追加（相手、権限、フォルダ、センター、経路） |
| 権限変更 | `add` の行があれば、その権限を更新。なければ `update` の行を追加 |
| 削除 | `add` の行があれば、その行を消す（本元にはまだない）。なければ `delete` の行を追加 |

- 上書きテーブルへの書き込みに失敗しても、操作自体は成功させる（翌日のレポートで反映されるだけ）。
- 範囲は SS 画面の操作だけ。Box で直接行った共有、グループのメンバーの出入り、フォルダの改名は、レポートを待つ。

**後始末（レポートの取り込みのあと）**
- 上書きの行のうち、**`created_at` が、取り込んだレポートの実行時刻より前のもの**を消す（その操作は、レポートに反映済み）。`delete` の行も同じ。
- 「レポートに載ったか」ではなく**実行時刻との比較**にする理由: レポートの実行（例 3:00）と取り込み（例 4:00）の間に操作（例 3:30）があると、その操作はレポートに入っていない。時刻で比べれば、この行を誤って消さない。実行にかかる時間に備えて、余裕を持たせる。
- 安全策として、**3 日より古い行は無条件で消す**（取り込みの失敗が続いたとき用）。

## 5. 一覧表示のロジック

ランチャーを開いたとき、サーバーが DB だけで組み立てる。

### 5.1 手順
1. ログインユーザーの所属・ゲストのセンターと、ユーザーが属するグループを取得する（既存の処理）。
2. `collaboration_report`（本元）から、`collaborator_login` がログインユーザーのメールアドレスの行を取る。
3. 上書きテーブルを重ねる。
   - `delete` の `collaboration_id` の行を除く。
   - `update` の `collaboration_id` の行は、権限を置き換える。
   - `add` の行のうち、相手が自分（メールアドレス）、または自分が属するグループのものを足す。
4. `center_folder_id` が手順 1 のセンターに含まれるものを除く（所属と共有の二重表示を防ぐ）。
5. `item_id` ごとにまとめる。同じフォルダに複数のコラボレーションがあるときは、**強い権限** を採用する（編集者 > ビューアー。Box でも強い権限が有効になる）。
6. センターのマスタを `center_folder_id` で引いて、表示名を付ける。センター名、フォルダ名の順に並べる。

### 5.2 SQL の目安
```sql
WITH base AS (
  -- 本元: 削除された分を除き、変更された権限を置き換える
  SELECT r.collaboration_id, r.item_id, r.item_name, r.center_folder_id, r.center_name, r.path_names,
         COALESCE(u.permission, r.permission) AS permission
  FROM collaboration_report r
  LEFT JOIN collaboration_overlay u ON u.collaboration_id = r.collaboration_id AND u.op = 'update'
  WHERE LOWER(r.collaborator_login) = LOWER(:email)
    AND NOT EXISTS (SELECT 1 FROM collaboration_overlay d
                    WHERE d.collaboration_id = r.collaboration_id AND d.op = 'delete')
  UNION ALL
  -- 上書き: 追加された分のうち、自分に関係するもの
  SELECT o.collaboration_id, o.item_id, o.item_name, o.center_folder_id, o.center_name, o.path_names,
         o.permission
  FROM collaboration_overlay o
  WHERE o.op = 'add'
    AND ((o.principal_type = 'user'  AND LOWER(o.principal_key) = LOWER(:email))
      OR (o.principal_type = 'group' AND o.principal_key IN (:userGroupKeys)))
)
SELECT item_id, item_name, center_folder_id, center_name, path_names,
       CASE MAX(CASE permission WHEN 'editor' THEN 2 ELSE 1 END)
            WHEN 2 THEN 'editor' ELSE 'viewer' END AS role
FROM base
WHERE center_folder_id NOT IN (:belongingCenterFolderIds)
GROUP BY item_id, item_name, center_folder_id, center_name, path_names;
```

### 5.3 API の応答（案）
既存の一覧に、`shared` を追加する。

```ts
type SharedAreaItem = {
  folderId: string;
  centerFolderId: string;
  centerName: string;      // センターのフォルダ名（英字）。フルパス・Box Drive のパス用
  centerLabel: string;     // センターの表示名（〇〇センター）。カードに出す
  pathNames: string[];     // センターより下の経路（フルパスは centerName + pathNames + folderName で組み立てる）
  folderName: string;      // Box 上のフォルダ名（カードの 1 行目と、フルパスの末尾に使う）
  role: "editor" | "viewer";
};
```

| コラボレーションの追加・変更・削除 | 今と同じ（Box の呼び出しは増えない。成功後に上書きテーブルへ書く） |
| レポートの取り込み | レポートの CSV の取得（出力のフォルダの一覧と、`Page_#` の数だけのダウンロード）。共有されたフォルダの数に比例しない |

## 7. 必要な API と処理

### 7.1 一覧（新規 API）
| 項目 | 内容 |
|---|---|
| 用途 | ランチャーの「共有された領域」の一覧 |
| 呼ぶ場所 | ランチャーを開いたとき（`getSharedAreas`） |
| 入力 | ログインユーザー（認証情報から。モックでは `userCd` を渡している） |
| 出力 | `SharedAreaItem[]`（5.3）。センター名、フォルダ名の順に並べ済み |
| 処理 | 5.1 の手順。DB のみ。**Box は呼ばない** |
| 依存 | 所属・ゲストのセンター（既存）、ユーザーが属するグループ（既存の所属テーブル。3.3）、センターのマスタ（3.2）、ユーザーのメールアドレス（3.3）、上書きテーブル（3.4） |

所属・ゲストのカードの一覧は、既存の API（DB の所属に応じて返す）のまま。

### 7.2 レポートの取り込み（バッチ。HTTP の API ではない）
4.2 のとおり。取り込みのあとに、上書きテーブルの後始末（4.4）を行う。実行の仕組み（cron など）と、CSV の取得方法は、未決（9 章）。

### 7.3 Box 管理コンソールでの設定（運用）
4.1 のレポート設定。コードではなく、運用の作業。

### 7.4 コラボレーションの追加・変更・削除（既存 API の変更）
画面（SS）が使う、コラボレーションの API（`BoxApi.createCollaborations` / `updateCollaboration` / `deleteCollaborations`）で、**Box の操作が成功したあとに、上書きテーブルへ書く**（4.4）。Box の呼び出し自体は変えない。上書きの書き込みの失敗は、操作の失敗にしない。

| API | 入力に足すもの | 上書きテーブル |
|---|---|---|
| 追加 `createCollaborations` | `centerFolderId`（SS 画面の `rootFolderId`）、`folderName`、`pathNames`（現在地の値。センターより下の経路）。相手は既存の入力（種類・識別子）を使う。相手がユーザーのときは、メールアドレスが必要 | `add` の行を追加 |
| 変更 `updateCollaboration` | なし（`collaborationId` と権限で足りる） | `add` の行なら権限を更新。なければ `update` の行を追加 |
| 削除 `deleteCollaborations` | なし（`collaborationId` で足りる） | `add` の行なら消す。なければ `delete` の行を追加 |

- 画面（フロント）の変更は、追加のときに、上の入力を送る部分だけ。一覧の API の応答は変わらない。
- センター直下への共有（`folderId` = `centerFolderId`）は、上書きに入れない（所属・ゲストのカードで出る）。

## 8. 弱点と、許容する点

| 項目 | 内容 | 扱い |
|---|---|---|
| 反映の遅れ（SS の操作） | SS 画面の追加・変更・削除は、上書きテーブル（3.4、4.4）で即時に反映する | 対策済み（上書きの書き込みに失敗したときだけ、最大 1 日遅れ） |
| 反映の遅れ（それ以外） | Box で直接行った共有、グループのメンバーの出入り、改名が、ランチャーに出るまで最大 1 日 | 許容。画面に「情報は毎日更新されます（最終更新: ○月○日）」と案内する。レポートの回数を増やせるなら、増やす（4.1 の繰り返しを 1 日 2 回などに） |
| Box Drive のパス | 改名の直後から、次の取り込みまで、正しく開けないことがある | 許容（押すたびに Box で最新を取る方式は、API の消費のため採らない）。画面に「Box Drive で開けないときは、Web Box を使ってください」と案内する |
| 取り込みの失敗 | 失敗すると、古い内容のまま | 前回の内容を残して通知する（4.2） |
| 行数 | グループ宛ては、メンバーの人数分の行になる。大きなグループで、レポートの行数が増える | 上限は文書に記載がない。実際の件数で確認 |
| 個人情報 | レポートにはメンバーの名前・メールアドレスなどが入る | 取り込む列を絞る（3.1）。CSV の置き場所と、取り込み後の扱いに注意 |
